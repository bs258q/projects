7-Week Deep Dive

LangChain — Full Teaching Path

Stage-by-stage curriculum with hands-on projects, twist exercises, debug challenges, and live assessments.

⚠️ Before starting LangChain: Students must build the same LLM call using raw requests first. This prevents the "black box" problem. If they can't debug without the framework, they can't debug with it.
Stage 1 — LangChain Foundations
Week 1–2 · Prereq: Python functions, APIs, JSON parsing, basic OOP
🧠Understand What LangChain Actually Is
▼
Why this matters
Students who skip this treat LangChain as magic. They can't debug it when it breaks.
What to teach
→LangChain is just a set of abstractions over LLM API calls — nothing more
→Core primitives: Model, Prompt, Chain, Memory, Tool, Agent
→LangChain Expression Language (LCEL) — the pipe syntax: prompt | model | parser
→When to use LangChain vs raw API calls (answer: raw API first, always)
→LangChain vs LangGraph vs LlamaIndex — when to use what
Hands-on exercise
Write the same LLM call 3 ways: raw requests library → OpenAI SDK → LangChain. Compare the code. Understand what LangChain adds.
💬Chat Models & Prompt Templates
▼
Why this matters
Everything in LangChain is built on top of these two primitives. Master them first.
What to teach
→ChatOpenAI / ChatAnthropic / ChatGoogleGenerativeAI — they all share the same interface
→SystemMessage, HumanMessage, AIMessage — the message format
→ChatPromptTemplate.from_messages() — building reusable prompt templates
→PromptTemplate variables: {'{variable}'} injection and validation
→invoke() vs stream() vs batch() — when to use each
Hands-on exercise
Build a prompt template that takes {'{role}'}, {'{tone}'}, and {'{task}'} as variables. Test with 5 different combinations. Observe how output quality varies.
📤Output Parsers
▼
Why this matters
Raw LLM output is unstructured text. Production apps need structured data. This is the bridge.
What to teach
→StrOutputParser — simplest, just returns text
→JsonOutputParser — parse JSON from LLM output
→PydanticOutputParser — validate output against a schema
→with_structured_output() — cleanest way to get typed output
→Handling partial/malformed outputs without crashing
Hands-on exercise
Build a resume parser: given raw resume text → extract {'{name, skills, experience_years, last_company}'} as a typed Pydantic model. Handle cases where fields are missing.
⛓️LCEL Chains
▼
Why this matters
LCEL is the core of modern LangChain. Every real pipeline uses it. Students who don't understand the pipe syntax can't read anyone else's code.
What to teach
→The pipe operator |: each step receives output of previous step
→RunnablePassthrough — pass input through unchanged to next step
→RunnableParallel — run multiple chains in parallel, merge results
→RunnableLambda — wrap any Python function as a chain step
→Chaining: input → prompt | model | parser → output
Hands-on exercise
Build a 4-step LCEL chain: user question → translate to English → answer in English → translate answer back to user's language. No if statements allowed — pure LCEL.
Stage 2 — Memory & Conversation
Week 2–3 · Prereq: Stage 1 complete, basic understanding of state management
🗂️Conversation History
▼
Why this matters
Without memory, every message is a fresh conversation. Most real apps need context across turns.
What to teach
→MessagesPlaceholder — where history gets injected into the prompt
→ChatMessageHistory — in-memory store of messages
→RunnableWithMessageHistory — wraps any chain with history management
→session_id — how to maintain separate histories per user
→The danger of unlimited history: token costs grow linearly
Hands-on exercise
Build a tutoring chatbot that remembers what topics a student has already covered. After 10 messages, it should refuse to re-explain things already taught.
📦Memory Management at Scale
▼
Why this matters
Keeping full history in context blows up costs. Real apps need smart summarization or retrieval.
What to teach
→ConversationSummaryMemory — summarize old messages, keep recent ones
→Token-based trimming: keep last N tokens, not last N messages
→Storing history in Redis or Postgres for multi-session persistence
→Selective memory: only store "important" turns
→Memory vs RAG: when to use each for context
Hands-on exercise
Take the tutoring bot from above. Add a Redis backend so history persists after server restart. Cap total history at 2000 tokens using smart summarization.
Stage 3 — RAG with LangChain
Week 3–4 · Prereq: Understand what embeddings are (run a numpy similarity search by hand first)
📄Document Loading & Chunking
▼
Why this matters
Garbage in, garbage out. Bad chunking is the #1 reason RAG systems give bad answers.
What to teach
→Document loaders: PyPDFLoader, WebBaseLoader, CSVLoader, DirectoryLoader
→TextSplitter types: RecursiveCharacterTextSplitter (default), TokenTextSplitter
→Chunk size vs chunk overlap tradeoff
→When semantic chunking beats fixed-size chunking
→Metadata: always attach source, page number, timestamp to every chunk
Hands-on exercise
Load the same 20-page PDF with 3 different chunk sizes (256, 512, 1024 tokens). For 10 test questions, measure which chunk size gives the most relevant retrieval. Write down your findings.
🗄️Embeddings & Vector Stores
▼
Why this matters
The embedding model choice matters as much as the LLM. Students need to understand this before they can debug bad retrieval.
What to teach
→OpenAIEmbeddings vs HuggingFaceEmbeddings vs CohereEmbeddings
→FAISS (local, fast) vs Chroma (local, persistent) vs Pinecone (cloud)
→vectorstore.add_documents() vs from_documents()
→Similarity search: cosine vs dot product vs euclidean
→MMR (Max Marginal Relevance) — avoiding redundant retrieved chunks
Hands-on exercise
Build the same RAG system with 2 different embedding models (OpenAI + all-MiniLM). Ask 10 domain-specific questions. Compare which model retrieves better. Explain why.
🔍Retrieval Chains
▼
Why this matters
This is where the full RAG pipeline comes together. Students should be able to build this from scratch by end of this step.
What to teach
→create_retrieval_chain() — the full RAG pipeline in LCEL
→create_stuff_documents_chain — stuff all retrieved docs into context
→RetrievalQA vs ConversationalRetrievalChain — history-aware retrieval
→Contextual compression: re-rank retrieved chunks before stuffing
→Multi-query retrieval: generate 3 versions of the question, retrieve for each
Hands-on exercise
Build a RAG system on a real dataset (your CV, a company's FAQ, a textbook chapter). Add source citation to every answer. If the answer isn't in the docs, the system must say so — not hallucinate.
Stage 4 — Tools & Agents
Week 5–6 · Prereq: Stage 3 complete, understand function calling at the API level
🛠️Tools & Tool Calling
▼
Why this matters
Tools are what turn an LLM from a text generator into an agent that can take actions.
What to teach
→@tool decorator — wrapping any Python function as a LangChain tool
→Tool schema: name, description, args_schema (Pydantic) — description quality matters enormously
→bind_tools() — attaching tools to a model
→Parsing tool calls from model response
→Built-in tools: TavilySearch, WikipediaQueryRun, PythonREPL
Hands-on exercise
Build 3 custom tools: get_weather(city), calculate(expression), search_docs(query). Make an LLM that picks the right tool for each of 10 test questions. Analyze when it picks wrong and why.
🤖ReAct Agents
▼
Why this matters
The ReAct pattern is the foundation of all agents. Understand this before touching LangGraph.
What to teach
→ReAct loop: Thought → Action → Observation → Thought...
→create_react_agent() with a list of tools
→AgentExecutor: max_iterations, handle_parsing_errors, verbose
→When agents get stuck in loops (and how to prevent it)
→Streaming agent intermediate steps to the user
Hands-on exercise
Build a research agent: given a topic, it must (1) search the web, (2) read 2 pages, (3) write a 200-word summary with 3 citations. Add a max_iterations=10 guard. Test with 5 topics.
🕸️LangGraph for Reliable Agents
▼
Why this matters
ReAct agents are unpredictable at scale. LangGraph gives you explicit control over agent flow — essential for production.
What to teach
→StateGraph: nodes (functions) + edges (conditions) + state (TypedDict)
→add_node(), add_edge(), add_conditional_edges()
→State: shared dict that flows through all nodes
→Human-in-the-loop: interrupt_before a node for approval
→Checkpointing: save + restore agent state (for long-running tasks)
Hands-on exercise
Rebuild the research agent from above using LangGraph instead of AgentExecutor. Add a human approval step before any web request is made. Compare reliability between versions.
Stage 5 — Production & Observability
Week 7 · Prereq: FastAPI basics, Docker fundamentals
🔭LangSmith Tracing
▼
Why this matters
You cannot debug or improve what you cannot see. LangSmith makes every LLM call visible.
What to teach
→LANGCHAIN_TRACING_V2=true — one env var enables full tracing
→Runs, traces, spans — understanding the hierarchy
→Datasets: build an eval dataset from real production traces
→Evaluators: correctness, relevance, faithfulness — automated scoring
→Feedback: thumbs up/down from users → training signal
Hands-on exercise
Add LangSmith tracing to your RAG system. Run 20 test questions. Find the 3 worst-performing queries in LangSmith. Fix them. Verify improvement with a re-run.
🚢Serving with FastAPI + Docker
▼
Why this matters
A LangChain app that only runs in a notebook is not a product. This step is non-negotiable.
What to teach
→FastAPI: POST /chat, POST /ask, GET /health endpoints
→Async with LangChain: .ainvoke(), .astream()
→Streaming responses via StreamingResponse + Server-Sent Events
→Environment variables: OPENAI_API_KEY, LANGCHAIN_API_KEY via .env
→Docker: containerize the app, bake no secrets into image
Hands-on exercise
Take any completed LangChain project. Wrap it in FastAPI. Add streaming. Dockerize it. Deploy on a free EC2 t2.micro or Railway.app. Share a working URL.

Capstone
AI-Powered Incident Response Bot
Week 7–8
LangGraphLangSmithPagerDuty APISlack APIFastAPIDocker

💡 The adaptive principle: Students who can only do what the tutorial showed aren't job-ready. Every exercise here forces them to transfer knowledge to a new context. The discomfort is the point.
🔀
Twist Exercises
After every project, give students a modified version that the tutorial doesn't directly solve. This forces transfer — the real learning.
Starting point
Built a FAQ chatbot on one PDF
The twist
Now make it work on a folder of 50 PDFs. Add a filter: only search PDFs from the last 30 days. How does retrieval quality change with 50x more data?
Teaches
Scalability thinking, metadata filtering, retrieval at scale
Starting point
Built a single-agent research bot
The twist
Split it into 2 agents: one that only searches, one that only writes. They communicate through a shared state. Neither can do the other's job.
Teaches
Multi-agent design, separation of concerns, shared state
Starting point
Built a prompt template with 3 variables
The twist
Now make the prompt dynamically change based on user's detected language and expertise level (beginner/expert). No hardcoded English prompts allowed.
Teaches
Dynamic prompt construction, few-shot adaptation, i18n thinking
Starting point
Built a RAG chain
The twist
Your vector DB just went down. Rebuild the retrieval layer using only BM25 keyword search (no embeddings). Compare answer quality. Write a 1-page analysis.
Teaches
Fallback design, BM25 vs semantic search tradeoffs, resilience thinking
Starting point
Built a chatbot with in-memory history
The twist
Now simulate 3 users chatting simultaneously. Make sure User A's history never leaks into User B's session. Load test with 10 concurrent users.
Teaches
Session isolation, concurrency, production-scale thinking
🔒
Constraint Challenges
Artificial constraints force students to think deeply instead of reaching for the obvious solution.
Starting point
Build a working RAG chatbot
The constraint
Budget constraint: total cost must be under $0.01 per user question. Measure your current cost with tiktoken. Optimize until you hit the target.
Teaches
Cost awareness, prompt compression, model selection, caching
Starting point
Build an agent that answers questions
The constraint
No internet access allowed. The agent can only use tools that read local files. It must still answer questions about current events using only what's in your documents.
Teaches
Working within constraints, knowledge base design, honest uncertainty
Starting point
Build a document summarizer
The constraint
The document is 200 pages — too long for any context window. You cannot use map-reduce. Design your own strategy to handle it.
Teaches
Context window management, chunked summarization, creative problem solving
Starting point
Build a LangChain app that works
The constraint
Now remove LangChain entirely. Rewrite it using only the raw OpenAI SDK and Python. The output must be identical.
Teaches
Deep understanding of what frameworks actually do, debugging skills
Starting point
Build a streaming chat endpoint
The constraint
Latency constraint: first token must arrive in under 500ms. Measure your current TTFT. Optimize. Show before/after measurements.
Teaches
Performance profiling, streaming optimization, SLO thinking

🔥 How to use these: Give students the setup + symptoms only. No hints. 30 minutes to diagnose. Only reveal hints if completely stuck. Never give the fix directly — make them find it.
The Silent Hallucinator
⭐⭐
A RAG chatbot that confidently answers questions about a company policy — but the answers are subtly wrong. The retrieved chunks look correct but the model is ignoring them.
Symptoms to show students
⚠ Retrieved chunks are relevant (score > 0.85)
⚠ Model answers look plausible
⚠ Answers are wrong in small but important ways (wrong dates, wrong percentages)
Hints (reveal one at a time)
💡 Check the prompt — is the instruction to "use only the context" strong enough?
💡 Is the model's training data conflicting with retrieved context?
💡 Try adding: "If the context says X, trust the context over your training data"
THE FIX
Strengthen the grounding instruction. Add "You MUST use only the provided context. Never use prior knowledge." Test with questions you know the ground truth for.
Teaches: Prompt grounding, RAG faithfulness, eval-driven debugging
The Retrieval Miss
⭐⭐
User asks "What is the cancellation policy?" — the answer is in the docs but the chatbot says it doesn't know. The chunk is in the vector store, but it's not being retrieved.
Symptoms to show students
⚠ Direct keyword search finds the right chunk
⚠ Vector similarity search misses it (score < 0.5)
⚠ Works for some questions, fails for others unpredictably
Hints (reveal one at a time)
💡 Print the actual scores of top-k retrieved chunks
💡 What's the semantic distance between "cancellation policy" and "how to cancel your subscription"?
💡 Try hybrid search: BM25 + vector. Does BM25 find it?
THE FIX
Add BM25 hybrid search. Alternatively, add semantic variants to the chunk metadata during indexing ("cancellation policy" → also tag with "cancel subscription, end plan, stop service").
Teaches: Semantic search limitations, hybrid retrieval, embedding space intuition
The Memory Leak
⭐⭐⭐
A multi-user chatbot where User A's conversation history starts leaking into User B's responses after 50+ concurrent sessions.
Symptoms to show students
⚠ Single-user tests work perfectly
⚠ Bugs only appear under concurrent load
⚠ User B receives answers referencing things only User A said
Hints (reveal one at a time)
💡 How is session_id being stored and retrieved?
💡 Is there a global variable storing the last used history object?
💡 Thread safety: is the history store thread-safe?
THE FIX
Ensure each request creates a new history instance keyed by session_id. Use Redis or Postgres as the backend (not in-memory dicts) to avoid state sharing between threads.
Teaches: Session isolation, concurrency bugs, production state management
The Infinite Agent Loop
⭐⭐⭐
A LangGraph agent that's supposed to research a topic and stop — but it keeps searching the same queries in a loop and never terminates.
Symptoms to show students
⚠ Agent output shows same tool call repeated 5+ times
⚠ Observation is non-empty but agent keeps searching
⚠ Hits max_iterations and returns empty result
Hints (reveal one at a time)
💡 What's in the agent's Thought before each Action?
💡 Is the agent updating its state after each observation?
💡 Does the agent have a clear stopping condition?
THE FIX
Add explicit state tracking: a list of "already_searched" queries in the state dict. Add a conditional edge: if len(state.searches) >= 5 OR state.has_enough_info → go to write_report node.
Teaches: Agent loop design, stopping criteria, LangGraph conditional edges, state design
The Slow RAG
⭐⭐
A RAG endpoint that takes 8 seconds to respond. Users are complaining. The LLM itself is fast (< 1s). Something in the retrieval pipeline is the bottleneck.
Symptoms to show students
⚠ LLM latency alone: ~0.8s
⚠ Full endpoint latency: ~8s
⚠ Adding more chunks makes it slower
Hints (reveal one at a time)
💡 Profile each step: time the embedding call, the vector search, the context building separately
💡 How many chunks are being retrieved and then re-embedded for reranking?
💡 Is the embedding call happening per-request or is it cached?
THE FIX
The bottleneck is almost always the reranker calling the embedding API per-chunk. Cache embeddings. Switch to a local reranker (cross-encoder). Reduce k from 20 to 5.
Teaches: Performance profiling, latency attribution, caching, retrieval optimization
The Token Bomb
⭐⭐
A document Q&A system that worked fine during testing but is now costing $50/day in production. Budget was $5/day.
Symptoms to show students
⚠ Costs 10x higher than estimated
⚠ Some requests cost $0.10, others cost $0.001
⚠ No error logs — everything succeeds
Hints (reveal one at a time)
💡 Log token counts for every request: prompt tokens + completion tokens
💡 Find the 95th percentile request by cost — what's different about those requests?
💡 Is there a user uploading huge documents that bypass chunking?
THE FIX
Add token counting before every LLM call. Set a hard limit: if prompt > 8000 tokens, truncate or refuse. Add input validation: max file size, max chunk count. Alert when cost/request exceeds threshold.
Teaches: Cost monitoring, token budgeting, input validation, production safety
